# Windows 弹幕与实时超分恢复

此补丁针对“弹幕和实时超分同时开启才会偶发画面停住、声音继续”的复现条件。它降低弹幕注入与绘制峰值，并监测 Windows 原生视频纹理的完成进展；不假定已证明某个单独根因。

## 已实施的防止措施

- Windows 视频输出使用四个共享纹理槽。D3D11 fence 未完成的槽不会被复用；Flutter 最近两次取用的共享纹理会各固定一个消费者轮次，避免合成器排队读取时被生产者覆盖。所有槽仍在使用时，mpv 跳过该次渲染而不是覆盖正在处理的纹理。提交后的 fence 通过 Flush 推进；Fence 报告设备移除时不当成成功完成。
- 合并 mpv 更新通知，每个视频输出最多挂起一个渲染任务；渲染线程与 Flutter 纹理回调之间只做非阻塞 fence 轮询，不等待 GPU 完成。
- 弹幕使用单个调度器，分散在一秒内发送。“限制弹幕数量”默认开启：Windows 超分开启时每秒最多注入 24 条、最多显示 72 条活动弹幕，其他情况分别为 60 条和 160 条；过期批次丢弃而不补发。关闭此开关后取消活动弹幕、每秒注入、候选条数和单次发送数量上限，也不因批次迟到而丢弃弹幕。设置页和播放中的弹幕设置均可切换并持久化，在下一次播放器更新时生效；已开始的当秒批次保持原策略，避免重复发送。弹幕画布按用户选择的帧率更新，默认 60 FPS；过长文本仍在栅格化前过滤。
- 透明度逐条应用于已栅格化的弹幕图像，移除覆盖整张画布的 Opacity 合成层。

## 临时恢复

仅当视频处于播放状态、非缓冲且播放位置推进时，监测原生纹理消费者回调的帧序号。启动或跳转后观察 2 秒；持续 500 毫秒无新帧则临时清空 Anime4K 着色器。检测到连续新帧后至少稳定 1.5 秒，并达到 2、4、8、16 或 30 秒退避期限后恢复原档。若仍无输出，最迟 30 秒也会尝试恢复；成功稳定 30 秒会重置退避。seek、暂停、缓冲不会触发自动绕过。用户主动切换或关闭超分会覆盖自动状态。

本地状态只区分用户所选档位和临时生效档位，不写超分持久化设置。因此自动绕过不能永久关闭超分。

## 边界与验证

当前 mpv/Flutter 共享纹理接口只提供着色器后的输出纹理，不能在着色器执行卡死时单独取得“超分前原始画面”并立刻覆盖显示。因此此处的兜底是停止后续超分工作并在输出恢复后自动重放所选档位，不承诺 GPU 已提交工作可以中断，也不承诺零时延原画覆盖。

原生槽位策略有独立 C++ 延迟 fence、乱序完成与 10,000 次轮换测试；恢复状态机和弹幕调度器有 Dart 测试。完成最终 Windows 构建后，仍需在有弹弹 play API key 的官方复现环境进行长时间 A/B：弹幕/超分分别单开作对照，再同时开启并覆盖超过此前最长故障间隔。检查 `SR recovery` 日志中的绕过、恢复事件和原生渲染统计。GPU/驱动长时间稳定性不能由离线单元测试代替。
